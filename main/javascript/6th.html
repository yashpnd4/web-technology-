AJAX and Asynchronous Web Applications

← Back to JavaScript Overview

1. What is AJAX?

AJAX stands for Asynchronous JavaScript and XML. It describes a technique in which JavaScript sends an HTTP request to a server and updates part of a webpage with the response without loading a completely new document.

JSON is common in modern applications, although the response can also contain text, HTML, XML, or another resource type. AJAX is a communication technique, not a server or database by itself.

2. Uses of AJAX

  • Searching a product or course list without reloading the page.
  • Refreshing messages or notifications.
  • Checking whether a username is available.
  • Submitting a form and showing the result on the same page.
  • Updating only the part of a page that needs new information.

3. AJAX Request and Response Cycle

  1. A user action or another event starts a request to a server URL, often called an endpoint.
  2. The browser sends the request, usually with GET to retrieve data or POST to send data.
  3. The server returns a response with a status and, when appropriate, a response body such as JSON or text.
  4. JavaScript checks the response, reads the body, and updates the required DOM elements.
  5. The rest of the document stays in place, and the page can show loading, success, or error feedback.

4. What Does Asynchronous Mean?

A synchronous operation makes the next step wait for the current operation to finish. Network requests can take time, so browser APIs such as fetch() work asynchronously and return a Promise representing work that will finish later.

The browser can continue responding to user events while the network request is being handled. An async function and await make asynchronous code easier to read. Await pauses that function until its Promise settles, not the whole browser interface.

5. Fetch API

Fetch is a modern browser API used to make HTTP requests. It returns a Promise that provides a Response object. The response body can then be read as JSON or text. 

async function loadCourses() {
    try {
        const response = await fetch("/api/courses");

        if (!response.ok) {
            throw new Error("HTTP error: " + response.status);
        }

        const courses = await response.json();
        console.log(courses);
    } catch (error) {
        console.error("Could not load courses:", error);
    }
}

loadCourses();

The example endpoint /api/courses is a placeholder. It must exist and return JSON for the example to work with real data.

6. Handling Errors

  • response.ok: Checks whether the HTTP status indicates success.
  • response.status: Gives the HTTP status code, such as 404 or 500.
  • response.json(): Reads the response body as JSON and returns a Promise.
  • try...catch: Handles network errors and errors raised while processing a response.

A Fetch request normally does not reject just because the server returned an HTTP error status such as 404 or 500. Check response.ok and handle unsuccessful statuses yourself.

7. What is CORS?

CORS stands for Cross-Origin Resource Sharing. A webpage can usually request resources from its own origin. If an API is hosted on a different origin, the server must allow the webpage to read the response through the correct CORS headers.

Using mode: "no-cors" is not a general solution because it produces an opaque response that JavaScript cannot normally read.

8. Important Points

  • AJAX updates part of a webpage without loading a new document.
  • JSON is a common response format, even though AJAX includes XML in its name.
  • Fetch is a modern API for making HTTP requests.
  • Fetch works asynchronously and returns a Promise.
  • Use async and await to write asynchronous code clearly.
  • Check response.ok because HTTP error statuses do not normally reject the Fetch Promise.
  • CORS controls whether a page can read responses from a different origin.
