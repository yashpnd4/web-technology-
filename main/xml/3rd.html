DTD and XML Schema (XSD)

1. What is XML Validation?

Well-formedness checks XML syntax, but it does not define which elements an application expects. A grammar defines the allowed elements, attributes, their order, and how often they may appear. An XML processor can use this grammar to validate a document.

2. What is DTD?

DTD stands for Document Type Definition. It is a compact grammar used to declare XML elements, attributes, entities, and content models. A DTD can be embedded inside an XML document or stored in an external .dtd file.

DTD syntax is not itself XML and it has limited data typing.

Example of catalog.dtd

<!ELEMENT catalog (product+)>
<!ELEMENT product (name, price)>
<!ATTLIST product id ID #REQUIRED>
<!ELEMENT name (#PCDATA)>
<!ELEMENT price (#PCDATA)>

This DTD requires one or more product elements. Each product must contain name followed by price, and every product must have an id attribute.

Matching catalog.xml

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE catalog SYSTEM "catalog.dtd">
<catalog>
    <product id="p101">
        <name>Notebook</name>
        <price>45.50</price>
    </product>
    <product id="p102">
        <name>Pen set</name>
        <price>30.00</price>
    </product>
</catalog>

3. What is XML Schema (XSD)?

XSD stands for XML Schema Definition. It is an XML-based grammar used to describe the structure and data types of an XML document. It supports built-in types such as decimal and date, constraints, namespaces, and reusable type definitions.

XSD is more expressive and strongly typed than DTD.

Example of catalog.xsd

<?xml version="1.0" encoding="UTF-8"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
    <xs:element name="catalog">
        <xs:complexType>
            <xs:sequence>
                <xs:element name="product" maxOccurs="unbounded">
                    <xs:complexType>
                        <xs:sequence>
                            <xs:element name="name" type="xs:string"/>
                            <xs:element name="price" type="xs:decimal"/>
                        </xs:sequence>
                        <xs:attribute name="id" type="xs:ID"
                                      use="required"/>
                    </xs:complexType>
                </xs:element>
            </xs:sequence>
        </xs:complexType>
    </xs:element>
</xs:schema>

This schema requires a product name, a decimal price, and an id attribute. It also specifies the order of child elements.

4. Connecting XML to an XSD File

To use an XSD schema, the XML root element can include the XML Schema instance namespace and the schema location. 

<?xml version="1.0" encoding="UTF-8"?>
<catalog
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:noNamespaceSchemaLocation="catalog.xsd">
    ...
</catalog>

5. Difference Between DTD and XSD

Feature DTD XSD
Grammar Format Uses specialized DTD syntax. Written using XML syntax.
Data Types Limited types, such as text and ID. Rich built-in and custom types, such as decimal and date.
Namespaces Limited support. Designed to support XML namespaces.
Typical Use Simple or legacy document formats. Detailed constraints and typed values.

6. Validating XML Files

The study guide uses the xmllint utility provided by libxml2 for validation.

Validate using DTD:

xmllint --noout --valid catalog.xml

Validate using XSD:

xmllint --noout --schema catalog.xsd catalog.xml

Save the XML and DTD files in the same directory. For XSD validation, use the schema location header and the matching XSD file.

7. Important Points

  • DTD and XSD define the permitted XML document structure.
  • DTD uses its own syntax and has limited data types.
  • XSD is written in XML and supports rich data types and constraints.
  • A valid XML document must also be well-formed.
  • xmllint can validate XML using DTD or XSD.
